# Netā-Nomics

A platform for following how MPs spend their local development funds. It reads MPLADS expenditure reports (mostly scanned PDFs), pulls every project out into a database, flags patterns worth a closer look, and helps citizens ask for data that has not been published.

Built by Sanay Krishna and Aniruddha Bhide at the Srujana Hackathon 2025, Chanakya University, where it placed 3rd.

## Why

Money under the Members of Parliament Local Area Development Scheme (MPLADS) is reported in PDFs that differ from one constituency to the next, and many are scanned images. Checking what was built, for how much, and by whom means reading them one by one. Netā-Nomics turns them into structured, searchable records.

## How it works

**Ingestion.** Report PDFs go into `backend/report_inbox/`. Calling `POST /api/v1/process/run` processes the inbox: each file is matched to a constituency by name, converted to images with `pdf2image`, read with Tesseract OCR, and sent to Gemini (2.0 Flash) in batches to extract each project's description, amount, location and contractor. The results are stored in PostgreSQL through SQLAlchemy.

**Red flags.** After a report is processed, two checks run over its projects:

- *Contractor concentration*: flags any contractor that received more than 40% of the constituency's reported spending.
- *Vague descriptions*: Gemini reviews project descriptions and flags ones too vague to audit.

Each flag is linked to the projects behind it. Clicking a flag in the dashboard asks Gemini for a short investigative brief based on those projects, including questions a journalist could put to the MP's office.

**Budget comparison.** For a constituency, Gemini proposes a needs-based budget split, which the dashboard shows as a pie chart next to the actual spending.

**Action hub.** For constituencies whose reports are missing or out of date, the app drafts an RTI application, a first appeal for when the RTI goes unanswered, and a preliminary PIL brief for a lawyer to review. These are drafts generated by a model and need a human to check them before use.

## Stack

- Backend: FastAPI, SQLAlchemy, PostgreSQL, Tesseract OCR, pdf2image (Poppler), Google Gemini
- Frontend: Next.js (pages router), React, TypeScript, Tailwind CSS, Recharts

## Run it

You need Python 3.10+, Node 18+, PostgreSQL, Tesseract and Poppler installed, and a Gemini API key.

**Backend**

```bash
git clone https://github.com/SanayKrishna/NetaNomics.git
cd NetaNomics/backend
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

Create `backend/.env`:

```env
DATABASE_URL=postgresql://USER:PASSWORD@localhost:5432/netanomics
GOOGLE_API_KEY=your-gemini-key
```

Then create the tables and seed the constituency list, and start the API:

```bash
python seed_db.py
uvicorn main:app --reload --port 8000
```

The Tesseract path is set for Windows (`C:\Program Files\Tesseract-OCR\tesseract.exe`) in `app/ai_pipeline.py`. Change it there on macOS or Linux.

**Frontend**

```bash
cd ../frontend
npm install
npm run dev
```

Open http://localhost:3000. The frontend uses `NEXT_PUBLIC_API_URL` and defaults to `http://127.0.0.1:8000`.

## API

| Method | Path | Purpose |
| --- | --- | --- |
| GET | `/api/v1/constituencies` | scorecards for all constituencies |
| GET | `/api/v1/dashboard/{name}` | projects, spending breakdown and flags for one constituency |
| POST | `/api/v1/process/run` | process new PDFs in the inbox |
| POST | `/api/v1/insights/detail` | investigative brief for one flag |
| POST | `/api/v1/budget/generate-optimal` | model-suggested budget split |
| POST | `/api/v1/legal/generate-docs` | RTI, first appeal and PIL drafts |
